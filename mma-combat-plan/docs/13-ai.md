### The 21 aggression inputs **[DATA]**
`health_head, health_body, health_leftleg, health_rightleg, delta_health, in_hit_reaction, idle, stamina,
opp_health_head, opp_health_body, opp_health_leftleg, opp_health_rightleg, opp_delta_health, opp_in_hit_reaction,
opp_idle, opp_stamina, opp_strike_activity, planner, round_num, round_time, score_differential`.
(Own state, opponent state, tempo, and match context. `planner` is the planner's own contribution.)

## 2. Recommended architecture **[REC]**

```
Perception  → FighterSituation (range, angles, cage flags, stamina/health %, current event, round clock, score diff)
Strategy    → aggression A∈[Amin,Amax] from the 21 factors   +  tendency desirabilities  (+ skills)
Tactics     → choose a goal type by weighted draw; choose a concrete action via per-goal selectors; check legality
Execution   → emit the *same intents* a human controller produces (strike slot/side/target, guard, move vector, grapple)
Timing      → difficulty curve: reaction delay, accuracy of reads, combo length, mistake rate
```

### 2.1 Aggression
```
A = clamp( A0[t] + Σ_i w_i[t] · curve_i(f_i) , Amin[t], Amax[t] )         t = tendency
curve_i(v) = 2v − 1 for health / stamina fractions (so a half-healthy fighter contributes nothing), v otherwise
f (own and opponent versions):
  head/body/leg health%, stamina%, delta_health (damage taken in the last 8 s), in_hit_reaction, idle time
  opp_strike_activity (strikes/s ÷ 3), round_time (elapsed/limit), round_num (n/total), score_differential (−1 losing … +1 winning)
  planner (bias hook; present, currently always 0)
```
Implemented weights (`ai.aggression.weights`, sign + = raises aggression; the other 11 factors exist with weight 0 so a designer
can switch them on): `opp_health_head −0.35` (hurt opponent ⇒ press), `opp_stamina −0.20`, `stamina +0.25`, `health_head +0.20`,
`in_hit_reaction −0.30`, `score_differential −0.25` (losing ⇒ push), `round_time +0.10` (late-round urgency), `idle +0.15`,
`opp_strike_activity −0.10`, `delta_health −0.15`. Base 0.5, global band 0.05–0.98; each tendency overrides `A0/min/max` and can
scale individual weights (`brawler A0 0.75 / min 0.45`, `chess_master A0 0.40 / max 0.75`, `attrition_specialist` ×2 on
`opp_stamina`, `adaptive_finisher` ×1.8 on `opp_health_head`).

### 2.2 Goal selection (planner-lite)
Goal types (observed): `strike, special_strike, loco, transition, takedown, clinch, submission` (+ defensive reactions).
```
score_g = base[t][g] · fit_g(situation) · (1 + interest_g) · U(0.9, 1.1) · aggressionGain(g, A)
aggressionGain = 0.5 + A for offensive goals (strike, special, takedown, clinch, submission, transition), 1.5 − A for loco
choose  = PROPORTIONAL weighted draw over score_g      # NOT a softmax: the first draft used softmax(score/τ); the shipped code
                                                       # draws proportionally so goal frequencies converge to the base table
```
* `fit_strike` = 1.6 if the opponent is mid-action or helpless, ×1.4 inside a counter window, 0.35 when nothing is in range;
  `fit_takedown` = `1.3 − 0.5·opp_strike_activity + 0.3·[opponent backed to the cage]` when a shot is legal, else 0 below 20
  stamina / 0.4 when close / 0.1; `fit_clinch` = 1 inside clinch range, 0.5 within 1 m, else 0.1; `fit_loco` = 1.8 when
  *you* are against the fence, 1.2 when far apart. Offensive fits are multiplied by an **energy factor** `0.5 + 0.5·stamina%`
  — tired fighters attack less and move more (an early version without it gassed out in round 1).
* `interest_takedown = clamp((takedown − opp.takedowndefense)/50, −1, 1)`; the same for clinch with `clinchcontrol`.
  (Submission interest uses own/opp stamina and the stage — the three observed factors — inside the ground logic.)
* Tendency base weights are data (`TENDENCY_PROFILES`), e.g. `striking_purist` strike .50 / loco .30 / special .08 / transition .10;
  `bjj_fighter` strike .22 / transition .25 / submission .17 / clinch .10 / takedown .06; `thai_clincher` clinch .18 / strike .34 /
  loco .15; `brawler` strike .62 / loco .12. Each profile also has strike preferences (limb and tag multipliers, e.g. `dirty_boxer`
  uppercut ×1.4, elbow ×1.4; `attrition_specialist` leg kicks ×1.5), a preferred fighting range and, for `off_the_back_specialist`,
  a bottom-game multiplier ×1.5.
* After picking a goal, a **selector** resolves details: strike → a feasible move (in reach, enough stamina) weighted by
  `(damage^0.8 · speed^0.5 · preference · U(0.9,1.1))^(1/τ)` (low τ = greedy, high τ = mistakes), chained into a combo through
  the cancel tags (`maxLen = clamp(1 + ⌊A·maxCombo⌋, 1, maxCombo)`); loco → approach / retreat / circle / escape-the-fence
  against the tendency's preferred range; takedown → direction and size; clinch → walk in then attempt.

### 2.3 Defence and reaction (difficulty)
`reactionTicks` (± jitter): beginner 26±8, pro 16±5, champion 8±3 — the delay between an incoming strike entering startup and
the AI being able to answer it. The AI only reacts to strikes that could reach it (within 1.15× reach). It then succeeds at *reading*
the strike with `p_def = clamp(base[difficulty] + 0.002·blocking − 0.10·[hands down], 0.02, 0.98)`
(beginner 0.30, pro 0.55, champion 0.78); on a failed read it takes the hit. What it does after a read: leg strike → low
guard (or step back 20 %); punches/teeps → parry timed to the impact (28 %), slip (50 %, needs movement ≥ 50), else guard at the
required height; body/head kicks → catch (30 %, if its style allows); 18 % step-backs (`chess_master` ×1.5 on the evasive
options). Between actions it holds its guard with probability `p_def`, re-rolled every 20–45 ticks, 20 % of the time low.
Sprawls against a shot with `0.7 · p_def`.

### 2.4 Commitment and cadence
A plan is committed until it finishes. After an **attack plan** the AI pauses `lerp(640, 230, A) ticks × U(0.7, 1.3)`
(`ai.gapTicks`, about 4–11 s) circling at its preferred range and holding its guard; after a movement-only plan it
re-decides in 12–24 ticks (`ai.rePlanTicks`). Clinch decisions come every `0.6 ×` and ground decisions every `0.9 ×` that gap. The long
stand-up pause is a calibration result: shorter gaps produced 150+ strikes per round (the design target is 40–80 thrown).
**Bout time budgets**: each new clinch gets a budget of 150–600 ticks (×1.6 for `thai_clincher`, `rounded_clincher`,
`dirty_boxer`), each ground bout 1200–2400 ticks, a `sprawl` position only 60–150 ticks. Past its budget the AI works to
end the bout (breaks the clinch, lets go of the ground control); it never ends it just because it is tired — an early version
that "released at 0 stamina" produced endless clinch/break loops.

**Finishing instinct (pounce)**: when the opponent goes down (`Mode.DOWN`) a standing brain decides once per knockdown, with
`p = clamp(0.3 + 0.7·A, 0, 0.95)`, whether to pounce; if so it drops its plan, walks to within 0.9 m and issues
`grapple:{kind:'followUp'}` inside the 150-tick window (`ground.downedFollowUpTicks`). On the ground a top fighter whose opponent
cannot defend (`isHelpless()`) enters **finishing mode**: strikes weigh ×8, transitions / submissions ×0.15, it never releases,
and it decides again every 6–15 ticks instead of every few seconds. Before this existed the AI ignored knockdowns entirely, so
TKOs were ≈ 1 % of fights and the KO:TKO mix was upside down (`19`). The legality checker treats `followUp` as the one grapple
intent that is legal without a bout.

### 2.5 Submission AI
On the ground the weight of a `submission` action is `(5·goals.submission + 0.25) · 0.5` (×1.5 for the off-the-back specialist
when on the bottom), among strikes, transitions, posture control and get-ups; the gate roll itself is in `10` §4. Inside a
session an **AI side never presses anything** — the minigame resolves by rule (`10` §3); an AI attacker aborts below 8 % stamina.

### 2.6 Optional: learning/playback ("style imitation") **[REC, inspired by RealAI]**
Log `(situation bucket → action, outcome)` rows from human fights; build per-fighter tables; the AI samples from them with
probability `imitation∈[0,1]` (difficulty-linked), else uses the archetype model. Storage format and bucketing in `18`.

### 2.7 Scripted AI for tutorials **[DATA]**
`ai_style="FTUE"` fights (`ftue_{blue,red}_corner_fight1..4.xml`) and `AiScriptedActionSubmission` show tutorials are
**scripted opponents**: expose a `ScriptedBrain` that replays a sequence of intents with trigger conditions.

### 2.8 Determinism rule for controllers
A brain draws only from its own named stream `ai.<fighterId>`. Those streams are **excluded from `World.stateHash()`** (`17` §7)
so a replay, which feeds recorded intents and never runs the brains, still matches the hash checkpoints taken in the live
fight. Anything a controller needs to randomise must use such a private stream, never a sim-owned one.

## 3. Acceptance tests (`reference/test/ai.test.js`, all passing)
1. All 12 tendency archetypes exist with complete, positive goal tables and sane aggression bounds.
2. Aggression is monotone in each factor in the documented direction; clamped to `[Amin,Amax]`; tendency overrides apply.
3. Over 5 000 draws under neutral conditions, goal frequencies converge to the tendency base weights (±3 %).
4. Reaction delay orders beginner > pro > champion; read probability orders the other way; hands-down hurts; champions defend more often end to end.
5. The AI never emits an illegal intent (all tendencies, three difficulties, full fights, debug checks every tick — 0 violations).
6. Same seed ⇒ identical decisions (event log and state hash); a different seed differs.
7. `ScriptedBrain` runs its steps in order, exactly once; `when` and `at` triggers work.
8. Forced goals (an ability proc) override the next draw; brains with ability bars press abilities.
